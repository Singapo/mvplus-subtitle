docs: state where each model actually comes from

The v0.1.2 notes left one gap open: the model list said what each tree is for
but not where to get it, and guessing a source would have been worse than saying
nothing. The provenance was recoverable from this machine instead of invented:
the Hugging Face cache still holds the five `models--<org>--<name>` directories,
each model card names its parent repository, and the licences were read from the
Hugging Face API rather than assumed.

docs/models.md now records, per model: the exact repository id, licence, size on
disk, the file the pipeline keys on (`model.bin` for the CTranslate2 trees,
`config.json` for the transformers ones), which feature needs it, and the `hf
download --local-dir` command to place it. Two constraints that were only in
code comments are now documented: the Japanese 760M tree requires
`ctranslate2 >= 4.7.1` (its card says the vocabulary changed), and the aligner
and verification stages need a `transformers` new enough to provide
`AutoModelForMultimodalLM` and `AutoModelForAudioClassification`.

Licences are reported as found, including the two `efwkjn` repositories that
declare none — that is a fact the reader has to act on, not something to smooth
over. The rest are MIT, Apache-2.0 and BSD-3-Clause.

README keeps the short placement table and links here for the download step.
