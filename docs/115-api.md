# 115 网盘接口：实测行为与必打补丁

这一页的目的：把「每次重装都要重新调教一遍」的接口知识固化下来。
所有 115 相关代码只允许写在 `cloud_common.py`，不要在别处再写一份。

## 认证

cookie 字符串来自浏览器，至少包含 `UID` / `CID` / `SEID` / `KID`，实际还常带
`USERSESSIONID` / `GST` / `PHPSESSID` / `acw_tc`。`mvsub doctor` 会检查四个关键字段。

cookie 过期**由人手工更新**。不要写脚本自动改写 `.env` —— 历史上就发生过「刷新脚本用一次失败的
响应覆盖了整份 `.env`，把可用 cookie 换成失效的」这种事故。

## 下载：只有一条路能用

```python
client.fs.get_download_info_from_pickcode(pickcode, user_agent="Mozilla/5.0 115disk/30.5.1")
```

三个接口的行为差异是实测出来的：

| 接口 | 结果 |
|---|---|
| `get_download_info_from_pickcode` + `115disk` UA | **可用**，走 app 加密接口 |
| 同一接口但不带该 UA | 报「请重新登录」 |
| `download_url_web` | 大文件报 `errno 50028 请使用115电脑端下载` |

另外：返回的 headers 里混有非字符串值，必须过滤后再交给 `httpx`，否则请求库会直接抛错。

## 上传：p115sync 有两个必打的补丁

### 1. `upload_gettoken` 信封校验

legacy 接口 `uplb.115.com/3.0/gettoken.php` 返回的是**扁平体**——
`StatusCode` / `AccessKeyId` / `SecretAccessKey` 等都在顶层，没有 `state` 也没有 `data`。
而 p115sync 用 `{state: True, data: {...}}` 的信封去校验，于是**成功响应被判成失败**：

```
P115APIError: 115 API 请求失败
```

这个 bug 极具误导性，因为它**只在 `status=1`（真传字节）时触发**；秒传命中（`status=2`）时
根本不调用这个接口，所以小文件、重复文件、以及「别人已经传过」的文件全都正常，只有真正要
传字节的大文件失败。

### 2. 尾片 Content-Length 声明过大

`_UploadWindowReader._declared_length()` 无条件返回 `max_bytes`（128 MB）。
当文件大小不是 128 MB 整数倍时，尾片实际不足 128 MB，OSS 拒收：

```
Too little data for declared Content-Length
```

结论：**任何非 128 MB 整数倍的大文件，Multipart 上传必然失败**。

### 3. 分片没有重试（附带修）

上游任一分片失败即整份从头上传。本项目补了分片级重试（`PART_TRIES = 6`）。

## 同名上传不会覆盖

这是最容易踩的一条：**同目录下同名上传不会覆盖，会并存两份同名文件**。
所以「把中文字幕传回视频旁边」不能用裸上传。

`cloud_common` 提供了两个事务方法：

| 方法 | 场景 | 行为 |
|---|---|---|
| `publish_missing_subtitle(video, local, journal, save)` | 原本没有字幕 | 先传到一个带 FID 的暂存名（`.mvplus-stage-<fid>.srt`），核对体积与 SHA1 后再改名成目标名；journal 记录每一步，崩溃后可续 |
| `replace_subtitle(original, local, backup, journal, save)` | 已有字幕要换 | 旧字幕改名加「旧」保留，再发布新件；每一次改名都写进 journal 以便回滚 |

两个都不信接口的 `state=True`：发布后必须重新列目录，核对**真实名字 / FID / 体积 / SHA1**。

暂存文件也用 `.srt` 结尾——115 的接口对扩展名敏感，用 `.part` 之类的后缀会让后续校验失败。

## 改名与删除

```python
client.fs_rename((fid, new_name))   # 注意是元组，参数顺序 (fid, name)
client.fs_delete(int(fid))          # fid 要是 int，传字符串会失败
```

`fs_rename` 的签名在不同 p115client 版本里出现过差异，`tests/test_cloud_subtitle_replace.py`
里有一条用例专门对着「本机已安装版本」的线上契约做断言，因此它被标成 `xfail`——换版本这个断言
本来就会变。

## 取音

让云盘侧直接抽音频（`extract_audio`）比整片下载再本地抽快得多，但**不能默认信它**：

- 分块取音时，每块必须核对长度；整片拼装后再核对总时长；
- FFmpeg 退出码 0 **不等于**时钟正确，必须比对 PCM 样本数与源 PTS；
- 未通过时长校验的音轨不得交给识别，更不能用「整体平移」去补所有片段。

## 代理

子进程里如果继承到 `*_proxy` 环境变量，会让直链下载走代理并失败。`nosub_sources` 里在起识别
子进程前会清掉所有名字带 `proxy` 的变量。
